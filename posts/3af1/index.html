数据库相关

主键和外键

主键是表中的唯一标识列，用于唯一标识每一行数据。主键的值必须唯一，且不能为空
唯一 非空 但可以是单列或组合列（复合主键）

外键是一个表中的列，引用了另一个表的主键，用于建立表之间的关联关系
一个主表可以有多个外键，可以为空
参照完整性：外键值必须在主表中存在，否则不允许插入数据。
FOREIGN KEY (user_id) REFERENCES users(user_id) ON DELETE RESTRICT

Mysql的聚合索引知道吗

MySQL InnoDB 的聚簇索引是指数据按照主键顺序存储，索引的叶子节点就保存了整行数据。它是表本身的数据结构，所以一张表只能有一个聚簇索引。相比辅助索引，它查找主键更快，不需要回表操作。

MySQL的索引，B+树性质。

InnoDB存储引擎，索引是通过 B+ 树实现的，
所有数据都存储在叶子节点，非叶子节点只存储索引键，这让非叶节点更小、更容易装入内存，提高了查找效率。
所有叶子节点之间通过链表连接，这使得 B+ 树非常适合执行范围查询，比如 BETWEEN 或排序类的 SQL 查询。

什么是装饰器和生成器

装饰器是一个函数，用来增强或修改另一个函数或类的功能，而不直接修改被装饰的函数的源代码。
常用于日志记录、权限验证、性能计时、缓存

def my_decorator(func):
    def wrapper():
        print("调用前")
        func()
        print("调用后")
    return wrapper

@my_decorator
def say_hello():
    print("Hello!")

say_hello()

生成器是一种用于创建迭代器的方式，它在函数中使用 yield 关键字，每次生成一个值，暂停函数执行，等待下一次调用。

def my_generator():
    yield 1
    yield 2
    yield 3

gen = my_generator()
for value in gen:
    print(value)

机器学习相关

逻辑回归原理 优缺点

逻辑回归虽然是回归，但是是一个二分类的统计模型
他的核心思想是通过sigmoid函数将数值映射到0-1的区间作为预测的概率

最小化损失函数（凸函数），通过梯度下降的方法

优缺点：
1模型简单，可解释性强 2效率高，运行快 3稳定性

1模型假定线性，非线性效果难以捕捉
2变量之间可能存在多重共线性
3特征工程要求比较高

在 sklearn 的 LogisticRegression 中，通过 penalty 和 C 参数来控制正则化强度。

LR中缺失值的常见处理方式

缺失值少 直接删除
均值 中位数 回归填补
机器学习算法填补 KNN填补 mice多重插补 missForest基于随机森林填补

SVM原理

是一种二分类模型，核心思想是寻找最优超平面，将不同类别的样本分开，实现最大化间隔；
可以分类，也可以用于回归

线性不可分的时候，引入松弛变量，最大化软间隔，允许部分样本被误分
或者使用核函数的方法，将数据投影到更高维度，在高维空间可分

损失函数 hinge loss + 正则化项

K-means原理

核心思想是通过最小化簇内样本点与簇中心的距离，来优化聚类效果。

初始化：随机选择 K 个样本点作为初始的簇中心
分配样本点：对于每一个样本，计算它与所有簇中心的距离，将其分配给最近的簇。
更新簇中心：对每个簇，重新计算所有属于该簇样本点的均值，作为新的簇中心。
迭代：重复“分配样本点”和“更新簇中心”两个步骤，直到簇中心不再发生明显变化，或达到最大迭代次数，算法收敛。

讲解决策树原理 还有优缺点

决策树是一种基于树结构的分类或者回归算法
通过不断选择最佳的特征不断分割数据集来建立一个树形的决策模型

ID3 信息增益 不能处理连续型变量和缺失值
C4.5 信息增益率 解决信息增益偏向高取值特征的问题
CART Gini系数

优缺点：
1易于理解和解释 2对数据要求低
1容易过拟合 2对噪声敏感

什么是剪枝

决策树容易过拟合，对训练数据拟合的很好，但是泛化能力差（低偏差，高方差）。所以需要剪枝防止过拟合。
剪枝的方法有预剪枝和后剪枝：
预剪枝通过优先设定比如最大深度，最小样本量，防止决策树长的非常复杂；
后剪枝先生成完整的决策树，然后进行剪枝，若效果变好，就保留剪枝。

讲解随机森林原理 优缺点

决策树容易过拟合
随机森林通过构建很多决策树（CART），对树的结果进行投票或者平均，提高稳定性和泛化能力

随机体现在：1通过bootstrap自助抽样，建模的数据子集随机；2随机选取特征子集建立决策树
优缺点：
1泛化能力强，不容易过拟合 2适用于高维数据，可以处理大量特征 3可以计算特征重要性
1计算成本高，运行时间长 2可解释性差

WOE分箱的目的和遵循原则

Weight of Evidence

图中分子分母好像要反一下

常用于LR
通过对变量进行分箱 计算每个箱的WOE值，使变量和目标变量之间的关系更符合线性假定

1.将非线性转化为线性
2.加快收敛、减少变量取值数量、提升计算效率
3.减少异常值影响、增加泛化能力避免过拟合

遵循原则：
1单调性
2每个分箱样本数量足够
3分箱不宜过多或者过少
4缺失值单独分箱 可能有实际业务意义

KS和IV，解释一下？

KS 基于累计分布函数的，用来衡量模型对不同类别的区分能力，数值越大，区分能力越强
IV 衡量变量的信息贡献，需要用于变量筛选

WOE 衡量每一箱对“好坏”的区分度；
IV 衡量整个变量的“预测能力”，越大越说明该变量越有用。

评分卡的刻度和实施

将用户的信用风险转换为一个易于理解的评分值
直接使用逻辑回归的 log(odds) 计算分数不直观，需要转换成标准评分区间（如 300-850）。

数据筛选

IV信息价值衡量变量对目标变量的预测能力 用于变量筛选
KS变量或模型的区分能力
稳定性 PSI 变量在不同时间段的分布状态 越小越稳定

PSI是计算模型预测出来的每个分数段内好坏客户的比例与实际样本好坏客户分布的差异性，
差异越小越好，一般认为PSI小于0.1时候模型稳定性很高，0.1-0.25一般，大于0.25模型稳定性差，建议重做。

相关系数 变量之间的线性相关关系 当存在高度线性相关时，需要考虑LR是否适用
逻辑回归显著性 系数的p值 VIF有无共线性 伪R方 McFadden’s Pseudo R²

两个变量相关系数高的话，应该删掉哪个？
LR中可以根据VIF删除更高的，还可以结合IV值判断变量的重要性

其次，大学的教育培养了我自学的能力，我觉得对于对于工作的内容可以很快的上手；
最后，我做事情负责，尽最大的努力，适应公司的岗位，在锻炼自己的同时，也为公司做出贡献。

你在工作中遇到过哪些挫折，是如何度过的

你遇到过最大的挫折是什么？

之前确实是比较顺利的，研一研二上课 竞赛 实习，都很充实。
研究生阶段，最大的挫折可能就是写论文的时候，
研三开始写论文，遇到重重的困难 数据不显著，实证做不出来，预答辩，需要换从头换指标体系，

自己内心抗住，要有坚定的信念可以克服。相信自己可以成功
然后做事情不能拖，不能觉得难，就不敢开始，只要有一点行动，接下来会逐渐上手，越来越好。
做事情要早做准备，规划好。

解决困难的经历、过往的挑战、难事如何结果

这里的话我想举我之前参加华为杯数学建模比赛的例子。
这个比赛呢，是要求在三四天的时间里完成一系列的建模分析，形成一篇论文，时间非常的紧急，通常需要熬好几天夜才能完成。
比如，我是编程手，当时也是一个二分类的问题，预测效果一直不好，accuracy上不来，进度停滞。数据不平衡会对结果造成较大的影响。
再比如遇到的坎坷，就是我和队友起了争执，我记得是我们之前做10折交叉验证。团队中沟通也是很重要的一点。

缺点，怎么避免呢

有时候比较追求完美吧，会对细节反复考虑，难以做出抉择。

这也是我一直寻求改进的，希望随着自己经历阅历的丰富，可以更加独立自主，做事果断一些。

优点是什么？

负责任、做事情有始有终、学习能力强

你有什么兴趣爱好？

我其实属于技术宅那种type。
在校的时候如果有同学约的会，周末会出去玩。
如果一个人的话，就宅在寝室看书、看电影，放松自己。

你对加班的看法？

如果是工作需要我会义不容辞加班。
我现在单身，没有任何家庭负担，可以全身心的投入工作。
但同时，我也会提高工作效率，减少不必要的加班。

工作中你难以和同事、上司相处

我会从自身找原因，仔细分析是不是自己工作做得不好让领导不满意，同事看不惯。还要看看是不是为人处世方面做得不好。如果是这样的话 我会努力改正。
如果我找不到原因，我会找机会跟他们沟通，请他们指出我的不足。有问题就及时改正。
作为优秀的员工，应该时刻以大局为重，即使在一段时间内，领导和同事对我不理解，我也会做好本职工作，虚心向他们学习，我相信，他们会看见我在努力，总有一天会对我微笑的！

如果不合适

首先我应聘这个岗位是经过深思熟虑的，而不是心血来潮的。

1 技能相符
2 更加努力

那你就要不断学习，虚心向领导和同事学习业务知识和处事经验，我相信这都是可以通过努力实现的

沟通上的挑战

有具体情境（真实冲突）；
有挑战点（观点强烈对立、时间紧张）；
有处理方法（共情 + 实验验证 + 中立第三方）；
有正向结果（融合方案 + 获奖）；
有反思提升（沟通的本质是协作达成共识）

我认为这次沟通之所以富有挑战，是因为双方都投入了很多努力，对各自的思路都比较坚持。而且，时间也比较紧，压力之下更容易情绪化。
我先冷静地分析了我们分歧的点在哪，是内容方向的不同，不是目标不同；最后我们请第三位队员，站在评委的视角给出反馈。
这个方式让讨论变得更理性，也把“对错之争”变成了“效果对比”。我们的论文也获得了省级二等奖的成绩。

这个经历让我意识到：良好的沟通不仅仅是说服，更是找到共同目标下最优解的过程。
而面对分歧，最关键的是保持尊重、换位思考，以及引导讨论聚焦在解决方案上。

“你和同事意见相左怎么办？”

工作中遇到分歧的是在所难免的。（表达了自己的心态很好。）
我会尽量站在对方的⻆度去理解这个问题，首先审视一下自己的认识有没有局限。（表达了会从自身找原因的态度。）
如果发现我的观点没有问题，那我会在坚持我最主要原则的前提下，多通过一些策略性的沟通方式，比如，多对对方的观点、付出的努力、观点的价值表示认可，然后阐述我自己考虑问题的出发点是什么，以此来争取对方的理解和支持。

与上级意见不一致

尊重上级，但有自己的独立思考；
用事实沟通，而不是情绪沟通；
即使不同意，也能积极执行；
关注最终业务效果，不内耗。

你认为最困难的沟通的问题是什么？为什么？

我认为最困难的沟通问题，是在目标一致但语言体系不同的团队中，如何让对方真正理解你的专业判断，并支持你的决策建议。
如果我直接抛结论或者用太技术化的语言，就很难达成一致。
所以我会特别注意“翻译”模型语言，用业务视角来解释策略背后的逻辑和数据支撑，让对方真正理解“我们为什么这么做”，以及“这么做的风险和收益权衡”。
我觉得最有效的沟通不是说服，而是让对方共情+共识+共赢。即使不能立刻达成一致，也要留下沟通的空间和信任的基础。

你认为良好沟通的关键是什么？

我认为良好沟通的关键有三个方面：共识目标、换位思考和及时反馈。

首先，沟通不是为了说服，而是为了达成共识。所以前提是双方要清楚在讨论什么问题、解决什么目标，而不是各说各话。
其次，换位思考特别重要，尤其是在跨职能合作中，比如数据岗和业务岗之间。如果我总是用技术术语解释问题，对方未必理解，也未必接受。所以我会主动站在对方视角思考：他们关心的是风险控制效果、业务转化率还是运营成本？然后再用他们能接受的方式讲清楚我的观点。
最后，沟通不是一次性完成的，而是一个有来有回的过程。我认为反馈机制和对齐结果很关键。及时确认理解是否一致，能减少误解和扯皮。

工作岗位应当具备哪些素质?

  1. 数据分析与建模能力：这是岗位的技术核心。能够熟练使用SQL进行数据提取，掌握Python等工具做数据清洗、特征工程，并熟悉常见的机器学习算法，如逻辑回归、决策树、XGBoost等。
  2. 业务理解力：风控本质上是“在业务前线做防火墙”，所以不仅要懂模型，还要理解贷前、贷中、贷后的业务流程与风险点，才能设计出真正有效的策略。
  3. 沟通协作能力：这个岗位会与产品、技术、业务方甚至外部合作机构频繁沟通，很多时候要用非技术语言解释技术方案，推进跨部门协作，需要清晰表达、换位思考和团队意识。
  4. 项目执行与落地能力：不仅是模型建好，更重要的是能推进策略落地，设计监控机制，并根据效果做快速迭代。所以执行力和项目跟踪意识也很重要。
  5. 学习与适应能力：这个岗位涉及到金融、数据、算法、合规等多个交叉领域，同时也会接触不同平台和场景，需要持续学习和快速上手新问题的能力。

你自己如何快速融入我们的团队

首先我会提高我的个人能力，高效的完成领导同事交代的各项任务，获得同事领导的认可。

做事要积极主动，给领导和同事们一个良好的印象，可以尽快与同事打成一片，融入公司团队。

说说你对行业、技术发展趋势的看法？

大数据时代

数据融合能力提升 和 智能化风控体系的演进。

从单一平台行为数据，扩展到多维度数据融合，比如：支付行为、电商、运营商、社交网络等
未来的重点会在于模型的解释性和自动化建模平台 AI
